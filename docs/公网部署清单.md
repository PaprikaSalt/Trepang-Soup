# Trepang Soup 公网部署清单

本文用于把当前 `v0.2.0` 服务端迁移到 Ubuntu 24.04 x86-64 公网服务器。架构和容量依据
见[后端实施指南](后端实施指南.md#21-性能与容量评估)。

## 0. 当前公网入口阻断

2026-07-31 从外部网络验证 `api.ljy32.cn` 时：

- `http://api.ljy32.cn/health` 返回 `Server: Beaver`、HTTP 403 和
  `Non-compliance ICP Filing`；
- `https://api.ljy32.cn/health` 在 TLS 握手阶段被远端重置；
- TCP 443 可建立连接，因此不是客户端 DNS 或本机断网；
- 服务端本机访问域名成功不能代替外部网络验收。

在此状态下，正式客户端默认的 `https://api.ljy32.cn` 无法从当前外部网络连接。发布给好友
前必须选择并完成一种入口方案：

1. 完成域名备案，继续使用当前 Caddy HTTPS 入口；
2. 临时按项目已接受的“不加密”约束，使用公网 IP 加非 80/443 端口。

临时公网 IP 方案建议：

```bash
# 不要在生产环境使用 --reload
uvicorn app.main:app --host 0.0.0.0 --port 8787
```

同时在云安全组和 Ubuntu 防火墙中仅开放实际使用的 TCP 端口。然后在一台不位于服务器内网
的电脑上验证：

```bash
curl --fail http://PUBLIC_IP:8787/health
python tools/smoke_transport.py --base-url http://PUBLIC_IP:8787
```

通过后重新构建客户端：

```powershell
$env:VITE_SERVER_URL = "http://PUBLIC_IP:8787"
pnpm tauri build
```

该方案会让会话令牌和游戏内容以明文传输，只适合作为已明确接受风险的小范围好友测试。
入口确认可用后，应同步修改 `client/src/config/server.ts` 的生产默认值，避免安装包仍指向
被拦截的域名。

## 1. 当前上线结论

当前代码可以进入 2C2G 公网服务器的部署和邀请制验收阶段。满足本文的环境、TLS、密钥、
备份和验收条件后，可以向受控测试用户开放。

不建议当前版本直接作为无访问限制的公开服务。完全公开前仍需完成：

- 按 IP 和玩家限制建房、加入、讨论及提问频率。
- 限制全局房间数、单房间讨论数和问题数。
- 增加运行中断线的自动退避重连与事件缺口恢复。
- 建立持续监控、告警、日志轮转和故障值班方式。

## 2. 推荐拓扑

```text
Windows 客户端
    │ HTTPS / WSS
    ▼
Caddy 或 Nginx（TLS、访问日志、连接限制）
    │ HTTP / WS，仅回环地址
    ▼
Uvicorn 单 worker：127.0.0.1:8787
    ├─ 内存房间、玩家会话和 WebSocket
    ├─ SQLite：/var/lib/trepang-soup/trepang.db
    └─ HTTPS 出站：DeepSeek API
```

必须保持一个 Uvicorn worker。活跃房间和会话是进程内状态，多 worker 会让 HTTP 与
WebSocket 请求落到不同状态空间。

## 3. 部署前准备

- Ubuntu 24.04 x86-64，建议至少 2C2G、10 GiB 可用磁盘。
- 一个解析到服务器的域名，以及可用的 TLS 证书自动续期方案。
- 仅对公网开放 TCP 80/443；8787 只监听 `127.0.0.1`。
- 允许服务器通过 TCP 443 访问 DeepSeek API。
- 创建无登录权限的 `trepang` 系统用户。
- 准备独立的生产 DeepSeek Key、管理员密码和会话签名密钥。
- 建议配置 512 MiB～1 GiB swap 作为意外峰值保护。

上线应部署一个明确的已验收提交，并记录：

```bash
git rev-parse HEAD
git describe --tags --always
```

不要在生产服务器上直接追随一个未经复验的移动分支。

## 4. 生产环境变量

在 `/opt/trepang-soup/server/.env` 保存：

```dotenv
APP_ENV=production
APP_HOST=127.0.0.1
APP_PORT=8787
PUBLIC_BASE_URL=https://api.example.com
CORS_ALLOWED_ORIGINS=["tauri://localhost","http://tauri.localhost"]
DATABASE_URL=sqlite+aiosqlite:////var/lib/trepang-soup/trepang.db

DEEPSEEK_API_KEY=<production-server-only-key>
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TIMEOUT_SECONDS=45
DEEPSEEK_MAX_CONCURRENCY=4
DEEPSEEK_RETRY_BASE_SECONDS=0.5
DEEPSEEK_GENERATION_ATTEMPTS=3
DEEPSEEK_TRUST_ENV=false

ADMIN_PASSWORD_HASH=<argon2id-verifier>
ADMIN_CHALLENGE_TTL_SECONDS=60
ADMIN_TOKEN_TTL_SECONDS=900
ADMIN_MAX_FAILURES=5
ADMIN_LOCKOUT_SECONDS=60
SESSION_SIGNING_KEY=<at-least-32-random-bytes>

ROOM_IDLE_SECONDS=14400
ROOM_CLEANUP_INTERVAL_SECONDS=30
ROOM_SETTLEMENT_GRACE_SECONDS=5
HOST_TRANSFER_SECONDS=90
MAX_ROOM_PLAYERS=20
RECENT_PUZZLE_WINDOW=10
```

生成管理员 verifier：

```bash
cd /opt/trepang-soup/server
source .venv/bin/activate
python tools/admin_credentials.py hash
```

可用 `openssl rand -hex 32` 生成会话签名密钥。`.env` 权限设为 `600`，不得进入 Git、
客户端、镜像、工单或日志。

## 5. 安装与服务

```bash
sudo apt update
sudo apt install -y python3 python3-venv sqlite3
sudo useradd --system --create-home --shell /usr/sbin/nologin trepang
sudo mkdir -p /opt/trepang-soup /var/lib/trepang-soup
sudo chown -R trepang:trepang /opt/trepang-soup /var/lib/trepang-soup
```

以部署用户安装锁定依赖：

```bash
cd /opt/trepang-soup/server
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
```

systemd 的核心启动命令：

```ini
ExecStart=/opt/trepang-soup/server/.venv/bin/uvicorn app.main:app \
  --host 127.0.0.1 \
  --port 8787 \
  --workers 1 \
  --ws-max-size 65536 \
  --ws-max-queue 16 \
  --limit-concurrency 200
```

如果 systemd 单元不接受上面的展示换行，将参数写在同一个 `ExecStart=` 行。服务用户只需
对 `/var/lib/trepang-soup`、日志目标和必要的运行目录具有写权限。

## 6. TLS 反向代理

反向代理必须：

- 将公网 HTTPS 请求转发到 `http://127.0.0.1:8787`。
- 传递 `Host`、真实客户端 IP、`Upgrade` 和 `Connection` 请求头。
- 允许 WebSocket 长连接并设置合理的读写超时。
- 限制 HTTP 请求体、连接速率和单 IP 并发连接数。
- 自动续期 TLS 证书，并在续期失败时告警。

不要把 8787 直接暴露公网作为正式运行方式。管理员挑战可以避免明文传输可复用密码，
但不能替代 HTTPS。

## 7. 客户端切换

Windows 客户端必须使用 HTTPS 服务地址重新构建：

```dotenv
VITE_TRANSPORT_MODE=server
VITE_SERVER_URL=https://api.example.com
```

执行：

```powershell
cd client
pnpm install --frozen-lockfile
pnpm build
pnpm tauri build
```

确认安装包版本与服务端协议版本一致。不要在客户端配置 DeepSeek Key、管理员 verifier
或会话签名密钥。

## 8. 数据迁移与备份

SQLite 只保存私人题库和近期抽题记录，活跃房间无法跨进程重启恢复。

首次部署可以创建空数据库。如果需要迁移现有题库：

1. 停止旧服务或暂停管理员写入。
2. 使用 SQLite backup 命令生成一致快照。
3. 把快照复制到 `/var/lib/trepang-soup/trepang.db`。
4. 修正文件所有者为 `trepang:trepang`。
5. 启动新服务并核对题目总数和随机抽题。

生产环境至少每日备份 SQLite，并保留异机副本。部署、回滚和恢复前都先创建新快照。

## 9. 上线前验收

在要部署的精确提交上完成：

```bash
cd server
ruff format --check .
ruff check .
mypy app tests tools
pytest -q
```

```powershell
cd client
pnpm install --frozen-lockfile
pnpm build
```

服务器启动后检查：

```bash
curl --fail https://api.example.com/health
cd /opt/trepang-soup/server
python tools/smoke_deepseek.py
python tools/smoke_transport.py --base-url https://api.example.com
```

还必须用生产候选客户端完成：

1. 管理员挑战登录。
2. 私人题目新增、编辑、停用和删除。
3. 私人题库建房并确认随机抽取。
4. 两个客户端加入、开局、讨论、AI 问答、提示和结算。
5. 断开再打开客户端后恢复最近一次有效会话。
6. 确认结算前的响应、WebSocket 事件和日志均不包含汤底。

## 10. 监控和放量

至少监控：

- 进程 RSS、CPU 和重启次数。
- 活跃房间数、在线 WebSocket 数和事件循环延迟。
- DeepSeek 请求延迟、并发等待数、429/5xx 和连续格式失败。
- HTTP 4xx/5xx、WebSocket 异常断开和管理员登录失败。
- SQLite 大小、备份成功时间、磁盘余量和日志增长速度。

2 GiB 服务器可在 RSS 超过 1.2 GiB 时预警，接近 1.5 GiB 时停止继续建房或人工限流。
先限制为少量邀请用户，观察至少一个完整使用周期，再逐步提高连接和房间上限。

## 11. 回滚

1. 停止服务并备份当前 SQLite。
2. 切回上一个已验收提交和对应依赖锁文件。
3. 如果数据库格式发生变化，恢复与旧版本兼容的快照。
4. 重新启动并验证 `/health`。
5. 运行双客户端冒烟测试。

服务器进程重启会让现有房间和玩家会话失效。部署和回滚应选择低峰期，并提前通知测试
用户。

## 12. 放行标准

邀请制公网测试需要全部满足：

- HTTPS/WSS 正常且 8787 未直接暴露。
- 生产密钥已注入、权限正确且没有进入 Git 或日志。
- systemd 单 worker 启动、自动重启和日志轮转正常。
- SQLite 备份和恢复至少演练一次。
- 服务端检查、客户端构建、真实 DeepSeek 和双客户端验收全部通过。
- 生产候选客户端已指向公网 HTTPS 地址。
- 已有基础主机防火墙、反向代理限流和资源告警。

无访问限制的完全公开服务还需满足：

- 应用层玩家命令速率限制已经实现并测试。
- 全局房间数、单房间历史和连接数具有硬上限。
- 运行中自动重连和事件缺口恢复已经实现并验证。
- 已完成目标峰值至少两倍的持续压力测试。
