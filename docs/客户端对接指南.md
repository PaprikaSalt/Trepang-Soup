# Trepang Soup 客户端对接指南

本文说明当前 Vue/Pinia 客户端与 FastAPI 服务的对接结构。主游戏传输链路已于客户端
`v0.1.1` 完成接入，私人题库管理于 `v0.2.0` 完成接入；服务端可根据配置使用 DeepSeek
或确定性开发主持人。正式公网部署仍必须补充 TLS、密钥管理和持续监控。

## 1. 当前可对接能力

| 能力 | 状态 | 入口 |
| --- | --- | --- |
| 健康检查 | 可用 | `GET /health` |
| 创建房间 | 可用 | `POST /api/v1/rooms` |
| 加入房间 | 可用 | `POST /api/v1/rooms/join` |
| 恢复并轮换令牌 | 可用 | `POST /api/v1/sessions/resume` |
| 房间快照与事件补发 | 可用 | `session.hello` |
| 房间、讨论和成员事件 | 可用 | WebSocket |
| 串行问答与撤回 | 可用 | WebSocket |
| 提示、结案和结算 | 可用 | WebSocket |
| 开局后加入 | 客户端已修复 | 按 `room.snapshot.room.stage` 导航 |
| 房内续局投票 | 客户端已预接入，等待后端 | `rematch.*` 与 `room.restarted` |
| DeepSeek | 服务端可用 | Key 只配置在 `server/.env` |
| 管理员私人题库 | 可用 | `AdminTransport` 与题库管理页 |
| 本地作答历史 | 可用 | WebView `localStorage`，不上传服务端 |

## 2. 开发地址

服务端默认：

```text
HTTP  http://127.0.0.1:8787
WS    ws://127.0.0.1:8787/api/v1/rooms/{roomId}/ws
```

Vite 开发地址 `http://127.0.0.1:1420` 已包含在服务端默认 CORS 白名单中。其他来源通过
服务端 `CORS_ALLOWED_ORIGINS` JSON 数组配置。

所有 `/api/v1` HTTP 请求必须发送：

```text
X-Protocol-Version: 1
Content-Type: application/json
```

## 3. 推荐客户端分层

不要让页面直接调用 `fetch` 或操作 WebSocket。建议新增：

```text
client/src/
├─ protocol/       线上的请求、命令、事件和枚举类型
├─ transport/
│  ├─ Transport.ts
│  ├─ MockTransport.ts
│  └─ ServerTransport.ts
└─ persistence/    roomId、playerId、sessionToken、lastEventId
```

`Transport` 负责连接和命令，Pinia 只接收快照或服务端事件并归并状态。现有页面不应理解
HTTP、WebSocket、令牌轮换或重连退避。

## 4. 建立房间连接

### 创建或加入

创建请求使用协议枚举，不发送界面中文：

| 界面值 | 协议值 |
| --- | --- |
| 新手 | `beginner` |
| 标准 | `standard` |
| 烧脑 | `hard` |
| 轻松日常 | `light_daily` |
| 经典悬疑 | `classic_mystery` |
| 暗黑惊悚 | `dark_thriller` |
| 荒诞幽默 | `absurd_humor` |

保存响应中的 `roomId`、`playerId`、`sessionToken` 和 `expiresAt`。`sessionToken` 不写日志，
不进入 Pinia 开发工具可见的公共房间状态。

AI 房间会在创建请求中完成题目生成和一次独立质量审查，客户端应允许最长 300 秒并显示
持续的创建中状态。网络超时后不要擅自假定房间未创建；首版客户端会向用户报告失败并保留
表单内容。

### WebSocket 握手

连接打开后第一条消息必须是：

```json
{
  "protocolVersion": 1,
  "commandId": "cmd_hello_<unique>",
  "type": "session.hello",
  "roomId": "room_...",
  "sessionToken": "opaque-token",
  "clientTime": 1785360000000,
  "payload": {
    "lastEventId": 0,
    "clientVersion": "1.1.0"
  }
}
```

首次连接或事件缓存无法覆盖缺口时收到 `room.snapshot`；正常重连时直接收到
`lastEventId` 之后的事件。

## 5. 客户端状态归并规则

1. `room.snapshot` 整体替换服务端派生状态，但不能清空输入框草稿。
2. 普通房间事件必须按 `eventId` 严格递增应用。
3. 小于等于当前 `lastEventId` 的普通事件是重复消息，直接忽略。
4. 发现跳号时停止应用后续普通事件，调用恢复接口并重新握手。
5. `protocol.error`、`session.rejected`、`command.rejected` 是连接级控制事件，应先处理，
   不参与公共事件序号递增。
6. 每个有副作用的命令生成稳定且全局唯一的 `commandId`；超时重试必须复用原 ID。
7. 只有 `game.settled` 或结算阶段快照可以包含 `truth` 和 `keyFacts`。

## 6. 断线恢复

建议使用 1、2、4、8、15 秒退避：

1. 记录最后成功应用的 `eventId`。
2. 调用 `POST /api/v1/sessions/resume`，提交旧令牌和 `lastEventId`。
3. 原子替换为响应中的新 `sessionToken`；旧令牌已经失效。
4. 使用新令牌重新连接 WebSocket 并发送 `session.hello`。
5. 收到快照或补发事件后清零退避。

同一玩家允许短暂存在多个 WebSocket 连接；只有最后一个连接断开时服务端才将玩家标记
离线。房主持续离线 90 秒后转移给最早加入的在线玩家。

## 7. 当前客户端实现

1. `src/protocol/` 定义协议版本、HTTP 响应、命令、事件和快照类型。
2. `src/transport/ServerTransport.ts` 负责 HTTP、WebSocket、命令等待与连接状态。
3. `src/persistence/session.ts` 仅在本机保存会话令牌、玩家身份和最后事件号。
4. `src/stores/game.ts` 统一归并房间快照与递增事件，并为离线界面预览保留模拟模式。
5. 页面只调用 Pinia 动作，不直接接触令牌、HTTP 或 WebSocket。

6. `src/transport/AdminTransport.ts` 在本机完成 Argon2id 与 HMAC 挑战计算，管理员令牌仅
   在内存中跨页面复用。
7. 题库管理页通过真实接口完成列表、新增、编辑、启停和删除，不提供导入导出入口。

目前支持应用重开后的房间会话恢复；运行中断线的自动退避重连与事件缺口自动恢复仍是
下一轮工作。

## 8. 联调基线

服务端启动后运行：

```bash
cd server
python tools/smoke_transport.py --base-url http://127.0.0.1:8787
```

输出 `{"status":"ok","clients":2,...}` 表示两个真实 WebSocket 客户端已完成从创建、
加入到 `game.settled` 的全流程，并且结算前未发现汤底字段。

开局后加入与房内续局的后端实施契约、状态机和验收步骤见
[续局投票与开局后加入协议](续局投票与开局后加入协议.md)。
