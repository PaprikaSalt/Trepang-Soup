# Trepang Soup 通信协议 v1

本文定义 Windows 客户端与后端之间的首版通信契约。实现后端时应以本文为基线；字段新增必须保持向后兼容，破坏性修改必须提升 `protocolVersion`。

## 1. 总则

- 协议版本：`1`
- 文本编码：UTF-8
- 时间：Unix 毫秒时间戳
- 房间邀请码：6 位大写字母或数字，排除 `0/O/1/I`
- HTTP基础地址：`http://<server-ip>:<port>/api/v1`
- WebSocket地址：`ws://<server-ip>:<port>/api/v1/rooms/{roomId}/ws`
- 单条讨论最大长度：180 个 Unicode 字符
- 单条正式问题最大长度：180 个 Unicode 字符
- 结案推理最大长度：800 个 Unicode 字符
- 昵称长度：1–16 个 Unicode 字符

所有客户端请求均发送 `X-Protocol-Version: 1`。版本不兼容时，服务端返回 HTTP 426 或 WebSocket `protocol.error`。

## 2. 通用消息封装

### 客户端命令

```json
{
  "protocolVersion": 1,
  "commandId": "cmd_01J...",
  "type": "question.submit",
  "roomId": "room_01J...",
  "sessionToken": "opaque-random-token",
  "clientTime": 1785360000000,
  "payload": {}
}
```

### 服务端事件

```json
{
  "protocolVersion": 1,
  "eventId": 1042,
  "type": "question.queued",
  "roomId": "room_01J...",
  "serverTime": 1785360000123,
  "causedByCommandId": "cmd_01J...",
  "payload": {}
}
```

规则：

- `commandId` 由客户端生成，全局唯一。
- 服务端在单个房间内递增 `eventId`。
- 同一个 `commandId` 重试时，服务端返回原结果，不重复执行副作用。
- 客户端保存最后成功应用的 `eventId`，断线重连时带上该值。
- 未知事件类型或未知可选字段必须被安全忽略。

## 3. HTTP接口


响应：

```json
{
  "roomId": "room_01J...",
  "inviteCode": "N7K4WM",
  "playerId": "player_01J...",
  "sessionToken": "opaque-random-token",
  "expiresAt": 1785367200000
}
```

### 3.3 加入房间

`POST /api/v1/rooms/join`

```json
{
  "inviteCode": "N7K4WM",
  "nickname": "小七",
  "clientInstanceId": "local-installation-id"
}
```

错误：

- `ROOM_NOT_FOUND`
- `ROOM_FULL`
- `NICKNAME_TAKEN`
- `ROOM_CLOSING`

### 3.4 恢复会话

`POST /api/v1/sessions/resume`

```json
{
  "roomId": "room_01J...",
  "sessionToken": "opaque-random-token",
  "lastEventId": 1042
}
```

响应返回新的短期 `sessionToken` 与房间快照版本。实际事件补发通过 WebSocket 完成。

响应：

```json
{
  "roomId": "room_01J...",
  "playerId": "player_01J...",
  "sessionToken": "rotated-opaque-random-token",
  "expiresAt": 1785367200000,
  "snapshotVersion": 1042
}
```

成功恢复后旧 `sessionToken` 立即失效。并发使用同一个旧令牌恢复时只能有一个请求成功。

### 3.5 管理员登录

先调用 `GET /api/v1/admin/challenge`：

```json
{
  "challengeId": "challenge_...",
  "nonce": "base64url-random-value",
  "issuedAt": 1785360000,
  "expiresAt": 1785360060,
  "mac": "hmac-sha256",
  "passwordKdf": {
    "name": "argon2id",
    "salt": "base64-value",
    "timeCost": 3,
    "memoryCost": 65536,
    "parallelism": 4,
    "hashLength": 32
  }
}
```

客户端使用专用管理员密码和返回参数计算 Argon2id verifier，再用 verifier 对以下 UTF-8
内容计算 HMAC-SHA256，并编码为 64 位小写十六进制：

```text
challengeId + "\n" + nonce + "\n" + issuedAt
```

随后调用 `POST /api/v1/admin/login`：

```json
{
  "challengeId": "challenge_...",
  "timestamp": 1785360000,
  "response": "64-character-hex-hmac"
}
```

成功响应：

```json
{
  "accessToken": "opaque-admin-token",
  "tokenType": "Bearer",
  "expiresAt": 1785360900
}
```

挑战 60 秒过期且只能使用一次；管理员令牌默认 15 分钟过期。题库请求发送
`Authorization: Bearer <accessToken>`。连续失败会触发短期限速。本节的 `issuedAt`、
`expiresAt` 和 `timestamp` 使用 Unix 秒，其余房间协议时间字段仍使用 Unix 毫秒。

该方案只能避免密码明文出现，不能抵御完整的中间人攻击。正式开放公网前仍建议切换 HTTPS。

### 3.6 私人题库

- `GET /api/v1/admin/puzzles`
- `POST /api/v1/admin/puzzles`
- `PUT /api/v1/admin/puzzles/{puzzleId}`
- `DELETE /api/v1/admin/puzzles/{puzzleId}`
- `POST /api/v1/admin/puzzles/import`
- `GET /api/v1/admin/puzzles/export`

列表响应：

```json
{
  "items": [],
  "total": 0
}
```

导入请求为 `{"mode":"upsert|replace","puzzles":[...]}`；导出响应包含
`schemaVersion`、`exportedAt` 和 `puzzles`。删除成功返回 HTTP 204。

题目对象：

```json
{
  "id": "puzzle_01J...",
  "title": "最后一班电梯",
  "surface": "玩家能够看到的汤面",
  "truth": "仅服务端和AI能够读取的完整汤底",
  "keyFacts": [
    "关键事实一",
    "关键事实二"
  ],
  "active": true,
  "createdAt": 1785360000000,
  "updatedAt": 1785360000000
}
```

## 4. WebSocket握手

客户端连接成功后发送：

```json
{
  "protocolVersion": 1,
  "commandId": "cmd_hello",
  "type": "session.hello",
  "roomId": "room_01J...",
  "sessionToken": "opaque-random-token",
  "clientTime": 1785360000000,
  "payload": {
    "lastEventId": 1042,
    "clientVersion": "0.2.2"
  }
}
```

服务端：

- 如果事件缓存仍覆盖 `lastEventId`，补发缺失事件。
- 否则发送完整 `room.snapshot`。
- 验证失败时发送 `session.rejected` 并关闭连接。

业务命令被拒绝时发送仅对当前连接可见的 `command.rejected`：

```json
{
  "protocolVersion": 1,
  "eventId": 1042,
  "type": "command.rejected",
  "roomId": "room_01J...",
  "serverTime": 1785360000123,
  "causedByCommandId": "cmd_01J...",
  "payload": {
    "error": {
      "code": "NOT_HOST",
      "message": "只有房主可以执行这个操作。",
      "retryable": false,
      "details": {}
    }
  }
}
```

`protocol.error`、`session.rejected` 和 `command.rejected` 是连接级控制事件，不推进
公共房间事件序号。客户端应先处理这些控制事件，再把其余事件交给严格递增的房间状态归并器。

## 7. 房间快照

`room.snapshot` 必须包含：

```json
{
  "room": {
    "roomId": "room_01J...",
    "inviteCode": "N7K4WM",
    "stage": "playing",
    "hostPlayerId": "player_01J...",
    "source": "ai",
    "difficulty": "beginner",
    "style": "classic_mystery",
    "hintCount": 1,
    "createdAt": 1785360000000,
    "startedAt": 1785360300000
  },
  "self": {
    "playerId": "player_01J...",
    "nickname": "海盐"
  },
  "players": [],
  "puzzleSurface": {
    "id": "runtime-puzzle-id",
    "title": "门缝里的光",
    "surface": "汤面"
  },
  "questions": [],
  "timeline": [],
  "discussions": [],
  "lastEventId": 1042
}
```

结案前绝不包含：

- `truth`
- `keyFacts`
- DeepSeek系统提示词
- 其他服务端秘密

## 8. 心跳与重连

- 服务端每 20 秒发送 WebSocket ping。
- 60 秒内未收到响应则标记玩家离线。
- 客户端使用 1、2、4、8、15 秒退避重连。
- 重新连接成功后清零退避。
- 房主离线 90 秒后转移房主。
- 玩家恢复连接时，以服务端快照为权威，不能把本地未确认状态覆盖到服务端。

## 9. 错误封装

```json
{
  "code": "QUESTION_ALREADY_PROCESSING",
  "message": "这个问题已经交给主持人，不能撤回。",
  "retryable": false,
  "details": {}
}
```

推荐错误码：

- `PROTOCOL_VERSION_UNSUPPORTED`
- `SESSION_INVALID`
- `ROOM_NOT_FOUND`
- `ROOM_FULL`
- `NICKNAME_TAKEN`
- `NOT_HOST`
- `INVALID_ROOM_STAGE`
- `QUESTION_NOT_FOUND`
- `QUESTION_ALREADY_PROCESSING`
- `AI_TEMPORARILY_UNAVAILABLE`
- `RATE_LIMITED`
- `VALIDATION_ERROR`
- `INTERNAL_ERROR`

## 10. 客户端应用事件的约束

- 按 `eventId` 严格递增应用。
- 小于等于最后事件 ID 的消息视为重复并忽略。
- 发现事件跳号时立即请求恢复，不猜测中间状态。
- `room.snapshot` 会整体替换房间派生状态。
- UI草稿不属于服务端状态，应用快照时不应被清空。
